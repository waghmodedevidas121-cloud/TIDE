Prototype Map Design

One handcrafted bathymetry. Not random, not procedural — handcrafted, because the question is whether a designed map produces routing decisions. A random map would confound "terrain matters" with "this layout happens to matter."

48 × 48 · 2,304 cells 4-fold symmetric Handcrafted 5 named features

01 Design rules

  1. Every landmass at least 4 cells thick. So terrain reads as silhouette, not as per-cell detail. This is what makes 8 px/cell legible on a phone.
  2. Four-fold symmetry. No spawn is advantaged, and rotation of the map changes nothing. Without this, a 1v1 comparison is worthless.
  3. Two route types must exist between any two points. One fast and exposed, one slow and safe. If only one route exists, there is no decision and the prototype measures nothing.
  4. At least one chokepoint. Contested ground must be able to be denied, or territory has no strategic value.
  5. Sand is never claimable. The claimable area is fixed at 1,872 cells, so 100% is a real target and the map can never be exhausted.
  6. Shallow water always fringes sand. Never a bare deep edge against sand — the slow margin must be the default approach, or the speed rule never comes into play.

02 The five named features

FeatureShapeWhat it is for
A. The Deep RunOpen ocean, outer 7-cell ring, entirely deepThe fast highway. Exposed, high traffic, no cover. The map's answer to "I want to move quickly."
B. The BarsFour 20×2 sand bars, one per sideForce a decision on approach: cross the bar and reach the mainland fast, or run the long way around in deep water. First route choice a player meets.
C. The Shallows3-cell shallow band on the seaward face of every landmassThe safe margin. Half speed, but it hugs landmass and never crosses open ocean. Rewards route planning over reflex.
D. The Mainland20×20 sand block, centre of mapSolid obstacle. Unclaimable, impermeable, and the reason the lagoon is a puzzle.
E. The Lagoon & Keyholes12×12 deep pool inside the mainland, reached by four 4-cell shallow passagesThe prize and the chokepoint. 144 cells of prime deep water, unreachable without committing to one of four narrow gaps — and sand blocks the capture, so you must loop around the mainland to close it. The single best test case in the map.

03 The map

Read it as three concentric bands

Ocean (fast, open) → Bars (obstacle, choice) → Shallows (slow, safe) → Mainland (wall) → Keyholes (choke) → Lagoon (prize). Every decision in this map is one of those six transitions.
DEEP — passable, 1.00× speed, open
SHALLOW — passable, 0.50× speed, safe
SAND — impassable, unclaimable

NumberValueReasoning
Claimable cells1,872Small enough that a 3-minute test session contains many captures, so many routing decisions. If the map were Paper.io's 10,000, a player would make three captures per session and we would learn nothing.
Sand share18.8%Enough to force real routing, not so much that the map feels like a maze. Above ~30% it becomes a corridor puzzle; below ~10% it stops mattering.
Lagoon144 cells7.7% of the claimable map — roughly a fifth of a winning territory — behind a 4-cell gate. High enough value that players will attempt it, which is the observation we need.
Keyhole width4 cellsWide enough to be findable by a new player, narrow enough that it feels like a commitment. At 2 cells nobody attempts the lagoon; at 6 it stops being a chokepoint.
Shallow share27.6%Enough slow terrain that the speed rule is always relevant, but still a minority so players must actively choose it rather than drift into it.
Shallow band width3 cellsWide enough to hug, narrow enough that hugging costs real time. One cell would be invisible; five would be a second ocean.
Deep Run thickness5–7 cellsA genuine open sea where the two players can circle each other without touching land. This is where aggression happens.

07 Route analysis — the decisions this map produces

JourneyFast routeSlow routeThe decision
Spawn → outer shelfDeep Run, around the bar endCross the bar's 2-cell shallowsClear trade. The first one a player meets.
Shelf → own territoryDeep Run, exposedHug the shallows at half speedSpeed vs. exposure. The core Paper.io skill, now terrain-driven.
Anywhere → LagoonDirect keyhole approachNone. There is no alternative.A commitment, not a trade. Four identical options.
Lagoon → enclose itImpossible from insideLoop around the whole mainlandThe puzzle. Sand blocks the capture, so closing the loop requires a 40-cell perimeter run.
Row 4 is the most valuable thing in this map

Enclosing the lagoon requires driving a loop around the entire mainland, because sand blocks the flood fill and the lagoon has no other exit. That is not a bug in the capture algorithm — it is the most interesting decision the map can produce, and it arrives without a single new rule. It is the primary thing to watch for in playtest: do players discover it, and how long does it take them?

08 Failure modes of this map design

RiskSeverityWhat we would see, and the response
Concentric symmetry makes the map feel repetitive once both players know itHIGHExpected, and accepted for a prototype. A 1v1 map is learned in about two minutes. Mitigated later by map seeds — the terrain format supports them at no extra cost.
Nobody ever attempts the lagoonHIGHMeans the map has no prize and no chokepoint. Response: raise the lagoon to 10% of claimable area, or place an early-spawn landmark. Do not add a UI marker — that would be teaching the test.
Players hug shallows everywhere and never use the deepHIGHMeans the speed bonus is not worth the exposure. Response: raise deep speed or lower shallow to 0.4×. This is a tuning failure with a known dial.
Sand-blocked movement feels like the boat is brokenMEDOnly if sand is invisible. Mitigated by making it the only warm colour on screen. If it still reads badly, add a 1-cell impact marker.
Unreadable at 8 px/cell on a phoneMEDMitigated by the 4-cell minimum landmass thickness, which is why rule 1 exists. Verified in M7.
The map is so safe that nobody diesLOWActually the desirable failure. Death comes from your own tail, which is the fair kind.
Enclosing the lagoon is impossible, not just hardHIGHWould be a capture-algorithm bug, not a design outcome. Verified explicitly in M6 before any playtest.

Everything except GRID and the map file itself is tunable at runtime, so a playtest can sweep values without a rebuild. That matters because the most likely useful discovery from the prototype is the speed ratio is wrong — and we should be able to find the right value in one session rather than three.
